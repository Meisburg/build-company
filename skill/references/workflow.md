# Skill workflow

## Intake

Ask for the company/project name, customer, problem, current hypothesis,
constraints, existing tools/repositories, lifecycle stage, and runtime (or
“generic”). Keep the intake short; mark inferred assumptions.

## Select the team

Always propose a human decision owner and an orchestrator. Add researcher,
customer voice, product, builder, growth, and reviewer roles only when their
inputs and outputs are distinct. Explain omitted roles.

## Scaffold

Create or update a `company/` folder containing a brief, decision log, evidence
vault, backlog, metrics, and feedback-triage file. Create selected role cards
with company context filled in. Add the validate-to-launch playbook and runtime
adapter notes. Do not overwrite existing records without asking.

## Verify

Check that every selected role has bounded permissions and a stop condition,
that handoffs point to real artifacts, and that no routine performs external or
irreversible actions without human approval. Report generated files, assumptions,
and missing capabilities.
